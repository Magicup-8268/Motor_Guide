# Magicup 원클릭 포털 재사용 지침

- 작성일: 2026-07-13 (KST)
- 적용 대상: 여러 웹서비스를 검색하고 즉시 여는 한국어 개인·팀용 포털
- 기준 버전: `magicup-one-click-portal` 로컬 우선 PWA

## 1. 이 템플릿의 정체성

이 프로젝트는 **서비스를 찾는 시간보다 바로 실행하는 시간을 줄이는 포털**이다. 기본 흐름은 `작업 보드 → 카테고리 지도 → 서비스 디렉터리`이며, 로그인 없이 각 기기 브라우저에 개인 상태를 저장한다.

다른 프로젝트에 재사용할 때는 외부 서비스의 브랜드명, 문구, 그래픽, 화면 배치의 복제가 아니라 아래의 **문제 해결 구조와 상호작용 규칙**만 가져간다.

| 유지할 것 | 새로 만들 것 |
| --- | --- |
| 검색, 카테고리, 즐겨찾기, 최근 방문, 전체 카드 열기 | 앱 이름, 로고, 문구, 서비스 데이터, 색상, 장식 그래픽 |
| 로컬 우선·로그인 없음 | 히어로 메시지와 오늘의 추천 기준 |
| PC·모바일 반응형, PWA, 공유 이미지 | 카테고리 개수와 서비스 분류 |

## 2. 기본 제품 규칙 (Reference)

1. **로그인을 기본값으로 넣지 않는다.** 즐겨찾기·최근 방문·클릭 수는 해당 기기의 `localStorage`에만 저장한다.
2. **서비스 카드의 빈 영역을 누르면 대상 사이트를 새 탭으로 연다.** 복사·즐겨찾기·열기 같은 세부 버튼은 독립적으로 동작해야 한다.
3. **검색은 서비스명·설명·태그를 동시에 탐색**하고, `Ctrl/Cmd + K`로 언제든 검색창을 연다.
4. **오늘의 추천은 예측 가능해야 한다.** 현재 구현은 연중 일자와 서비스 배열을 이용해 하루에 한 개를 고른다.
5. **외부 링크는 안전한 새 탭으로 연다.** `window.open(url, "_blank", "noopener,noreferrer")`를 사용한다.
6. **핵심 기능은 장식보다 우선한다.** 애니메이션은 시선을 빼앗거나 어지럽게 만들면 제거한다.

### 현재 저장 키

새 프로젝트에서는 접두사만 새 앱명으로 바꾼다. 데이터 형식 변경 시에는 키 이름도 올려 이전 데이터와 충돌하지 않게 한다.

| 상태 | 현재 키 | 권장 새 프로젝트 키 |
| --- | --- | --- |
| 테마 | `magicup:theme:magic-night` | `<app>:theme:<mode>` |
| 즐겨찾기 | `magicup:favorites` | `<app>:favorites:v1` |
| 최근 방문 | `magicup:recents` | `<app>:recents:v1` |
| 클릭 수 | `magicup:clicks` | `<app>:clicks:v1` |

## 3. 구현 구조 (Reference)

```text
src/
├─ App.tsx                 화면 조립, 검색·저장·외부 열기 상태
├─ styles.css              디자인 토큰, 반응형, 모션
├─ components/Icon.tsx     아이콘 이름을 Lucide 아이콘으로 연결
├─ data/categories.ts      카테고리 목록
├─ data/sites.ts           서비스 목록과 URL·태그·노출 가중치
├─ main.tsx                React 진입점과 NanumGothic 번들 로드
└─ types.ts                Category / Site 타입
public/
├─ magicup-logo-4k.png     원본 보관용 4K 로고
├─ magicup-logo.png        화면 표시용 최적화 로고
├─ og-cover.png            SNS 공유 표지(1200 × 630)
├─ manifest.webmanifest    PWA 앱 정보
└─ sw.js                   오프라인 셸 캐시
```

서비스 데이터는 화면 코드에 직접 쓰지 말고 `src/data/sites.ts`에서 관리한다.

```ts
interface Site {
  id: string;
  name: string;
  description: string;
  url: string;
  icon: string;
  categoryId: CategoryId;
  tags: string[];
  weight: number;
}
```

- `id`: 변경하지 않는 영문 식별자
- `url`: HTTPS 우선, 실제로 열리는 공식 URL
- `tags`: 사용자가 검색할 법한 한국어·영문 키워드
- `weight`: 기본 노출 우선순위. 클릭 수가 쌓이면 별도 점수로 더할 수 있음

## 4. 화면과 디자인 규칙 (Explanation)

### 4-1. 정보 구조

1. **상단 바:** 로고, 현재 작업 보드, 카테고리 이동, 검색, 테마·설치 도구
2. **히어로:** 한 문장 후킹, 검색 진입 버튼, 오늘의 흐름
3. **요약 카드:** 오늘의 추천, 저장한 서비스, 최근 흐름
4. **서비스 지도:** 카테고리 전체를 한눈에 비교하는 카드 그리드
5. **디렉터리:** 필터된 서비스 목록. 행 전체 열기와 독립 액션을 제공

### 4-2. 독자적 디자인 원칙

- 다른 사이트에서 받은 인상은 분위기 참고로만 사용하고, 브랜드·카피·그래픽·레이아웃을 그대로 따라 하지 않는다.
- 현재 방향은 **Magic Night**: 짙은 밤 배경, 보랏빛 포커스, 구리색 브랜드 자산이다.
- 카드는 `18–26px`의 큰 모서리, 낮은 대비의 테두리, 하단의 은은한 광원으로 계층을 만든다.
- 포커스 색은 클릭 가능함을 알리는 데만 사용한다. 작은 글자를 보라색만으로 표현하지 않는다.
- 본문·제목·UI는 `NanumGothic` 400/700을 앱 번들에 직접 포함한다. 네트워크 글꼴에 의존하지 않는다.

### 4-3. 재사용 가능한 색상 토큰

새 브랜드에 적용할 때도 밝은 색부터 진한 색까지 7단계를 먼저 정의한 후 토큰에 매핑한다.

| 역할 | 현재 값 | 새 프로젝트 적용 기준 |
| --- | --- | --- |
| 배경 | `#03030F` | 가장 진한 브랜드 중립색 |
| 표면 | `#0D0D1F` | 배경보다 한 단계 밝은 패널색 |
| 기본 강조 | `#7955F6` | 버튼·포커스·핵심 강조색 |
| 보조 강조 | `#B69AFF` | 라벨·링·보조 강조색 |
| 본문 | `#F7F5FF` | 다크 배경에서 4.5:1 이상 대비 |
| 보조 본문 | `#C0B9D6` | 본문보다 낮지만 읽을 수 있는 대비 |

색상 전체 정의와 접근성 기준은 [DESIGN.md](../DESIGN.md)를 기준 문서로 삼는다.

### 4-4. 모션 안전 규칙

- 기본 전환은 `180ms` 이하, 화면 진입은 `300–420ms` 범위로 제한한다.
- 큰 이미지·로고·궤도는 회전·크기 변화·좌우 이동을 겹쳐 사용하지 않는다.
- 장식은 클릭 영역을 덮지 않으며 `pointer-events: none`을 사용한다.
- `prefers-reduced-motion: reduce`에서는 애니메이션과 전환을 사실상 제거한다.
- 현재의 촛불 장식은 작은 불꽃과 후광만 각각 `8.4s`, `12s`로 매우 약하게 변화한다. 새 프로젝트에서 눈 피로 의견이 나오면 가장 먼저 정적 이미지로 바꾼다.

## 5. 핵심 상호작용 구현 규칙 (How-to)

### 5-1. 행 전체 열기

카드 안에 버튼을 중첩하지 않는다. 행 전체 열기용 투명 버튼을 **형제 요소**로 두고, 실제 액션 버튼은 더 높은 `z-index`를 준다. 그래야 접근성·키보드 포커스·즐겨찾기 버튼이 모두 정상 동작한다.

```tsx
<article className="service-row">
  <button className="service-row-open-area" onClick={() => onOpen(site)}
    aria-label={`${site.name} 열기`} />
  <div className="service-copy">...</div>
  <div className="service-actions">복사 · 즐겨찾기 · 열기</div>
</article>
```

검수 기준은 세 가지다.

- 카드 본문 클릭: 정확한 서비스가 새 탭에서 열린다.
- 즐겨찾기 클릭: 새 탭이 열리지 않고 저장 상태만 바뀐다.
- 키보드 Tab/Enter: 전체 열기와 세부 버튼을 각각 조작할 수 있다.

### 5-2. 검색·추천·개인화

- 검색어는 `name`, `description`, `tags`를 소문자 기준으로 함께 비교한다.
- 최근 방문은 최대 10개만 유지하고, 동일 서비스는 맨 앞으로 이동한다.
- 인기 점수는 `weight + clicks * 3`처럼 이해 가능한 규칙으로 계산한다.
- 오늘의 추천은 `sites[dayOfYear % sites.length]`와 같이 하루 동안 변하지 않는 방식으로 만든다.
- 로그인·서버 동기화가 필요해지기 전까지는 기기 간 데이터 불일치를 정상 동작으로 안내한다.

### 5-3. 모바일 우선 검수

반응형 기준점은 현재 `900px`, `760px`, `480px`이다. 새 프로젝트에서 다음을 직접 확인한다.

- 360px 너비에서 검색, 히어로 카피, 촛불/장식, 버튼이 겹치지 않는다.
- 서비스 행의 전체 열기 영역이 복사·즐겨찾기 버튼을 가로채지 않는다.
- 가로 스크롤이 생기지 않는다.
- 텍스트가 한글에서 잘리지 않고, 44px 이상의 터치 영역을 확보한다.

## 6. 로고·공유·PWA 운영 (How-to)

### 6-1. 브랜드 자산

1. 새 프로젝트 로고의 원본은 `public/<brand>-logo-4k.png`로 보관한다.
2. 화면용 최적화본은 `public/<brand>-logo.png`로 분리한다.
3. 공유용 표지는 `public/og-cover.png`에 **1200 × 630px**로 만든다.
4. 히어로에는 로고를 반복 배치하지 않는다. 로고는 헤더·공유 표지에서 브랜드를 보증하고, 히어로는 행동을 안내한다.

### 6-2. SNS 미리보기

`index.html`의 Open Graph와 Twitter 이미지는 배포 후 반드시 절대 HTTPS 주소로 바꾼다.

```html
<meta property="og:url" content="https://<project>.vercel.app/" />
<meta property="og:image" content="https://<project>.vercel.app/og-cover.png" />
<meta name="twitter:image" content="https://<project>.vercel.app/og-cover.png" />
```

- 이미지 링크를 로컬 IP나 상대 경로로 두면 SNS가 이미지를 가져오지 못한다.
- SNS는 이전 미리보기를 캐시할 수 있으므로, 메타 태그를 바꾼 뒤 실제 공개 URL을 다시 공유해 확인한다.

### 6-3. PWA

- `manifest.webmanifest`의 앱 이름, 아이콘, 테마색, 시작 URL을 새 브랜드에 맞춘다.
- 서비스 워커의 캐시 이름은 `<app>-shell-v1`처럼 앱별·버전별로 바꾼다.
- 설치 버튼은 브라우저가 설치 프롬프트를 허용할 때만 보이도록 하고, 모바일·데스크톱에서 각각 확인한다.

## 7. 새 프로젝트 시작 절차 (Tutorial)

### 1단계 — 범위를 고정한다

아래 문장을 새 프로젝트의 첫 요구사항으로 사용한다.

> 한국어 원클릭 서비스 포털을 만든다. 로그인과 서버 동기화는 넣지 않고, 즐겨찾기·최근 방문·클릭 수는 각 기기 브라우저에 저장한다. 검색, 카테고리, 오늘의 추천, 카드 전체 열기, PWA 설치, SNS 공유 이미지를 제공한다. 기존 서비스의 브랜드·카피·그래픽·레이아웃을 복제하지 않고 새 브랜드와 독자적인 문구·자산을 사용한다. 글꼴은 NanumGothic 400/700을 앱 번들에 포함하고, PC와 휴대폰에서 모두 검수한다.

### 2단계 — 콘텐츠를 먼저 바꾼다

1. `src/data/categories.ts`의 이름·설명·색상·이모지를 새 서비스 분류로 교체한다.
2. `src/data/sites.ts`에서 URL이 실제 공식 사이트인지 확인하고, 설명과 태그를 새 사용자 언어로 쓴다.
3. 히어로의 앱명·후킹·추천 기준을 새 사용자 문제에 맞춘다.
4. `public/`의 로고, 파비콘, 공유 표지를 교체한다.

### 3단계 — 디자인을 적용한다

1. 7단계 팔레트를 만들고 배경·표면·강조·본문 토큰에 매핑한다.
2. 장식은 한 가지 주제만 선택한다. 예: 촛불, 별, 지도, 파동 중 하나.
3. 장식이 피로하거나 기능을 가리면 효과를 줄이는 대신 대비·간격·카피로 완성도를 만든다.

### 4단계 — 실행·배포한다

```powershell
npm install
npm run dev
npm run dev:lan       # 휴대폰 같은 Wi-Fi 테스트용
npm run build
npm run test:links
```

- PC에서는 `http://127.0.0.1:5173`으로 접속한다.
- 휴대폰에서는 PC의 IPv4 주소를 사용한다. `127.0.0.1`은 **각 기기 자신**을 뜻하므로 휴대폰에서 PC 서버 주소가 될 수 없다.
- Vercel 첫 배포 예시: `npx vercel@latest --prod --yes --name <project-name>`
- 배포 URL이 정해진 후 `index.html`의 OG 절대 URL을 바꾸고 한 번 더 배포한다.

## 8. 출고 전 체크리스트

- [ ] 브랜드명·문구·로고·공유 이미지가 새 프로젝트 고유 자산이다.
- [ ] 모든 서비스 URL이 열리고, 중요한 공식 링크는 자동 검사 또는 수동 검사했다.
- [ ] 카드 본문/즐겨찾기/복사/열기가 서로 충돌하지 않는다.
- [ ] `Ctrl/Cmd + K`, Escape, Tab, Enter를 키보드로 확인했다.
- [ ] 360px 모바일과 넓은 PC 화면에서 잘림·겹침·가로 스크롤이 없다.
- [ ] `prefers-reduced-motion`에서 장식 모션이 멈추거나 최소화된다.
- [ ] 빌드가 통과하고, 공개 URL·`/og-cover.png`·SNS 메타 태그가 모두 HTTPS 200 응답이다.
- [ ] 설치 버튼, 다크/라이트 테마, 로컬 즐겨찾기와 최근 방문을 새로고침 뒤 다시 확인했다.

## 9. 변경 판단 규칙

| 요청 | 기본 결정 |
| --- | --- |
| 여러 기기에서 즐겨찾기를 같게 보이게 해 달라 | 로그인/동기화 범위로 분리해 별도 설계한다. 현 로컬 우선 구조를 억지로 확장하지 않는다. |
| 서비스 목록이 자주 바뀐다 | 먼저 `sites.ts` 관리 흐름을 유지하고, 편집자가 여럿일 때만 CMS 또는 관리 화면을 검토한다. |
| 화면이 밋밋하다 | 대형 애니메이션보다 카피, 여백, 카드 계층, 약한 후광을 먼저 조정한다. |
| SNS 미리보기에 이미지가 없다 | 공개 HTTPS 절대 URL, 1200×630 이미지, 배포 후 캐시 순서로 확인한다. |
| 외부 레퍼런스와 너무 닮았다 | 카피·히어로 구조·카드 비율·장식·색상 중 최소 세 가지를 새로 설계한다. |
